# Reference Application Analysis

Findings from studying the reference application, used to guide our own architecture.

Planned sections:

- **Overview**: what the app does, its tech stack, how it's distributed
- **Architecture**: layers, modules, dependency structure
- **UI patterns**: shell/navigation, views, controls, theming
- **Data and file formats**: what it reads and writes (course files, assets)
- **Design patterns**: MVVM, commands, services, plugins, etc.
- **Takeaways**: what we adopt, adapt, or avoid
